Dodatek: Git i GitHub Lekcja 6 z 8

Klonowanie i stan repozytorium

Repozytorium zadania-html jest już na GitHubie, bo zadania 1-3 wgrałeś przez stronę WWW. Teraz pobierzesz jego kopię na komputer. To się nazywa klonowanie.

Adres repozytorium

Na stronie repozytorium kliknij zielony przycisk Code, wybierz kartę SSH i skopiuj adres. Wygląda tak:

git@github.com:johndoe/zadania-html.git

Wybierz adres SSH, a nie HTTPS. Wtedy Git użyje Twojego klucza z lekcji 5.

git clone: pobierz kopię

Wejdź do folderu, w którym ma być projekt, i wklej adres po git clone:

~ $ git clone git@github.com:johndoe/zadania-html.git
Cloning into 'zadania-html'...
remote: Enumerating objects: 12, done.
remote: Counting objects: 100% (12/12), done.
remote: Compressing objects: 100% (10/10), done.
remote: Total 12 (delta 2), reused 0 (delta 0), pack-reused 0 (from 0)
Receiving objects: 100% (12/12), done.
Resolving deltas: 100% (2/2), done.
~ $ cd zadania-html
~/zadania-html (main) $ ls
README.md	index.html

git clone tworzy folder zadania-html i pobiera do niego wszystkie pliki oraz całą historię. Linie remote: wypisuje GitHub. Klonujesz tylko raz na każdym komputerze. Potem już tylko pobierasz nowości przez git pull.

Po wejściu do folderu repozytorium znak zachęty pokazuje (main). To nazwa gałęzi, czyli linii historii. Na razie masz tylko jedną gałąź, main.

git status: co się dzieje

To najważniejsze polecenie. Używaj go zawsze, gdy nie wiesz, co dalej. Nic nie zmienia, tylko opisuje stan.

~/zadania-html (main) $ git status
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
  • On branch main: jesteś na gałęzi main.
  • up to date with 'origin/main': masz te same commity, co GitHub.
  • nothing to commit, working tree clean: od ostatniego commita nic nie zmieniłeś.

git log: historia

~/zadania-html (main) $ git log --oneline
cbbd694 (HEAD -> main, origin/main, origin/HEAD) Add files via upload
dae89b8 Update index.html
3d6c131 Add files via upload
e898b1e Initial commit
~/zadania-html (main) $ git log -1
commit cbbd694e87cf0e20064cfcc23d97d10525ac9347
Author: John Doe <john.doe@example.com>
Date:   Tue Sep 29 16:51:00 2026 +0200

    Add files via upload

git log --oneline pokazuje jeden commit w linii: skrócony hash i opis. Najnowszy commit jest na górze. Oznaczenia w nawiasie:

  • HEAD -> main: tu jesteś teraz;
  • origin/main: tu jest gałąź main na GitHubie (według ostatniej wiadomości od GitHuba).

Sam git log pokazuje więcej: pełny hash, autora i datę. -1 ogranicza wynik do jednego commita. Gdy historia jest długa, git log wyświetla ją stronami: spacja przewija, q wychodzi.

git remote: skąd jest kopia

~/zadania-html (main) $ git remote -v
origin	git@github.com:johndoe/zadania-html.git (fetch)
origin	git@github.com:johndoe/zadania-html.git (push)

Git pamięta, skąd sklonowałeś repozytorium, pod nazwą origin. Dlatego później wystarczy git push bez adresu.

Trzy miejsca, w których są Twoje zmiany

To najważniejsza idea Gita. Każda zmiana przechodzi przez trzy miejsca:

Porównanie: pakujesz paczkę. Na biurku masz rzeczy (katalog roboczy). Wybrane rzeczy wkładasz do pudełka (poczekalnia). Na końcu zaklejasz pudełko i piszesz na nim, co jest w środku (commit). Lekcja 7 pokazuje to na zadaniach 4 i 5.

Historia jest w ukrytym folderze .git w repozytorium. Nie zmieniaj go ręcznie i nie usuwaj go.

Ćwiczenie

  1. Skopiuj adres SSH swojego repozytorium.
  2. Sklonuj je do folderu ~/Documents/informatyka.
  3. Wejdź do folderu repozytorium i wykonaj git status.
  4. Policz commity w git log --oneline. Czy ta liczba jest taka sama, jak na GitHubie?

Sprawdź się

Ile razy klonujesz repozytorium na jednym komputerze?

Raz. Potem pobierasz nowe commity przez git pull.

Co znaczy working tree clean?

Pliki w folderze są takie same, jak w ostatnim commicie.

Wymień trzy miejsca, przez które przechodzi zmiana.

Katalog roboczy, poczekalnia (staging area), repozytorium (historia).
