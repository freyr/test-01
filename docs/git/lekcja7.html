Dodatek: Git i GitHub Lekcja 7 z 8

git add i git commit: zapisywanie zmian

Teraz zrobisz zadanie 4 na swoim komputerze i zapiszesz je jako commit. Zamiast wgrywać plik przez stronę WWW, użyjesz dwóch poleceń: git add i git commit.

Krok 1: zmień plik i sprawdź stan

Otwórz index.html w Notatniku, dopisz listy z zadania 4 i zapisz plik. Potem zapytaj Gita, co widzi:

# Edytujesz index.html (zadanie 4) i zapisujesz plik.
~/zadania-html (main) $ git status
On branch main
Your branch is up to date with 'origin/main'.

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   index.html

no changes added to commit (use "git add" and/or "git commit -a")

Git zauważył zmianę: modified: index.html. Napis Changes not staged for commit oznacza, że zmiana jest tylko w katalogu roboczym. Jeszcze nie ma jej w poczekalni.

Krok 3: git add, czyli zmiana do poczekalni

~/zadania-html (main) $ git add index.html
~/zadania-html (main) $ git status
On branch main
Your branch is up to date with 'origin/main'.

Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	modified:   index.html

git add nic nie wypisuje. git status pokazuje teraz Changes to be committed: zmiana jest w poczekalni i wejdzie do następnego commita.

Krok 4: git commit, czyli zapis w historii

~/zadania-html (main) $ git commit -m "Zadanie 4: wyliczenia i numerowania"
[main e32ebb1] Zadanie 4: wyliczenia i numerowania
 1 file changed, 69 insertions(+)
~/zadania-html (main) $ git log --oneline
e32ebb1 (HEAD -> main) Zadanie 4: wyliczenia i numerowania
cbbd694 (origin/main, origin/HEAD) Add files via upload
dae89b8 Update index.html
3d6c131 Add files via upload
e898b1e Initial commit

Git utworzył commit e32ebb1: 1 plik, 69 nowych linii. W historii HEAD -> main jest już o jeden commit dalej niż origin/main. Commit jest na razie tylko na Twoim komputerze. Lekcja 8 pokazuje, jak wysłać go na GitHub.

Nowe pliki: zadanie 5

W zadaniu 5 zmieniasz index.html i kopiujesz do folderu pięć obrazków. Nowych plików Git jeszcze nie śledzi:

# Zadanie 5: zmieniasz index.html i kopiujesz do folderu 5 obrazków .gif.
~/zadania-html (main) $ git status
On branch main
Your branch is ahead of 'origin/main' by 1 commit.
  (use "git push" to publish your local commits)

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   index.html

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	grafika1.gif
	grafika2.gif
	grafika3.gif
	grafika4.gif
	grafika5.gif

no changes added to commit (use "git add" and/or "git commit -a")

Untracked files to pliki, których nie ma w żadnym commicie. Git ich nie zapisze, dopóki nie dodasz ich przez git add. To częsty błąd: strona działa na Twoim komputerze, ale na GitHubie brakuje obrazków.

Zamiast wypisywać każdy plik, użyj git add .. Kropka oznacza bieżący folder, czyli wszystkie zmienione i nowe pliki:

~/zadania-html (main) $ git add .
~/zadania-html (main) $ git status
On branch main
Your branch is ahead of 'origin/main' by 1 commit.
  (use "git push" to publish your local commits)

Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	new file:   grafika1.gif
	new file:   grafika2.gif
	new file:   grafika3.gif
	new file:   grafika4.gif
	new file:   grafika5.gif
	modified:   index.html
~/zadania-html (main) $ git commit -m "Zadanie 5: animowane grafiki"
[main 12f2637] Zadanie 5: animowane grafiki
 6 files changed, 5 insertions(+)
 create mode 100644 grafika1.gif
 create mode 100644 grafika2.gif
 create mode 100644 grafika3.gif
 create mode 100644 grafika4.gif
 create mode 100644 grafika5.gif

Napis Your branch is ahead of 'origin/main' by 1 commit przypomina, że commit z zadania 4 nadal czeka na wysłanie. Po tym commicie czekają już dwa.

Przed git add . zawsze wykonaj git status. Sprawdź, czy na liście nie ma plików, których nie chcesz w repozytorium, na przykład Thumbs.db, .DS_Store albo prywatnych dokumentów. Repozytorium na GitHubie jest publiczne.

Dobry opis commita

Opis czytasz Ty za miesiąc i nauczyciel. Ma powiedzieć, co zmieniłeś, w jednym krótkim zdaniu.

Słaby opisDobry opis
zmianyZadanie 4: wyliczenia i numerowania
poprawkaPopraw link do strony szkoły
asdfDodaj 5 animowanych grafik
zadanie 4, 5 i 6trzy osobne commity, po jednym na zadanie

Rób commit po każdym skończonym kroku. Małe commity łatwo opisać i łatwo cofnąć.

Gdy się pomylisz

SytuacjaPolecenie

Ćwiczenie

  1. Zrób zadanie 4 w swoim repozytorium.
  2. Obejrzyj zmiany przez git diff.
  3. Dodaj plik do poczekalni i zrób commit z dobrym opisem.
  4. Zrób zadanie 5. Sprawdź, czy obrazki są na liście Untracked files, i zapisz wszystko jednym git add . i jednym commitem.
  5. Sprawdź git log --oneline. Ile commitów czeka na wysłanie?

Sprawdź się

Zrobiłeś git commit, ale Git pisze nothing added to commit. Co pominąłeś?

git add. Commit zapisuje tylko to, co jest w poczekalni.

Co znaczy Untracked files?

Nowe pliki, których nie ma w żadnym commicie. Dodaj je przez git add.

Zrobiłeś commit. Czy strona na github.io już się zmieniła?

Nie. Commit jest tylko na Twoim komputerze. Potrzebny jest git push.
