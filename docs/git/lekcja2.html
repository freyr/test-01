Git i GitHub: repozytorium rozproszone

Git i GitHub to dwie różne rzeczy. Ta lekcja wyjaśnia różnicę i pokazuje, gdzie jest Twoja historia.

Repozytorium (w skrócie repo) to folder projektu razem z całą jego historią. Repozytorium Johna nazywa się zadania-html.

Centralny i rozproszony system

Starsze systemy kontroli wersji są centralne. Historia jest tylko na jednym serwerze. Gdy serwer nie działa, nie możesz zapisać żadnej zmiany.

Git jest rozproszony. Każdy komputer, który ma repozytorium, ma pełną kopię całej historii. Możesz robić commity w autobusie bez internetu. Kopię na GitHubie aktualizujesz później jednym poleceniem.

Kopię na GitHubie nazywamy zdalnym repozytorium (ang. remote). Git nadaje jej krótką nazwę origin. Kopia na Twoim komputerze to repozytorium lokalne.

Kopie nie łączą się same. Ty decydujesz, kiedy wysłać i pobrać zmiany:

  • git push: wyślij moje nowe commity na GitHub;
  • git pull: pobierz z GitHuba commity, których jeszcze nie mam.

Gdzie tu jest GitHub Pages

GitHub Pages to dodatek GitHuba. Po każdym nowym commicie na GitHubie Pages bierze pliki z repozytorium i publikuje je jako stronę https://johndoe.github.io/zadania-html/. Nie ma znaczenia, czy commit przyszedł ze strony WWW, czy z git push. Po minucie lub dwóch strona jest aktualna.

Ważne: commit na Twoim komputerze nie zmienia strony w internecie. Strona zmienia się dopiero po git push.

Sprawdź się

Czy Git działa bez internetu?

Tak. Commity zapisujesz lokalnie. Internet jest potrzebny tylko do git push i git pull.

Co znaczy „rozproszony”?

Każda kopia repozytorium ma pełną historię. Żaden serwer nie jest jedynym miejscem, gdzie jest historia.

Co to jest origin?

Nazwa zdalnego repozytorium, czyli kopii na GitHubie, z którego sklonowałeś projekt.

Zrobiłeś commit, ale strona na github.io się nie zmieniła. Dlaczego?

Commit jest tylko na Twoim komputerze. Wykonaj git push.
