Zanim poznasz polecenia, zrozum, po co w ogóle jest Git. Ta lekcja nie wymaga komputera.

Problem: wiele wersji jednego pliku

Bez narzędzia folder z projektem po kilku tygodniach wygląda tak:

index.html
index_stary.html
index_dobry.html
index_dobry_POPRAWIONY.html
index_dobry_POPRAWIONY2_ostateczny.html
index_kopia_przed_zadaniem_5.html

Nie wiesz, która wersja jest najnowsza. Nie wiesz, co się zmieniło między wersjami. Jeśli nadpiszesz plik, poprzedniej wersji już nie ma.

Rozwiązanie: system kontroli wersji

System kontroli wersji zapisuje historię projektu. Masz zawsze jeden plik index.html, a program pamięta każdą jego zapisaną wersję. Najpopularniejszy taki program to Git.

Każdy zapis w historii to commit. Commit to zdjęcie całego projektu w jednej chwili. Każdy commit ma:

  • opis: jedno zdanie, co się zmieniło, na przykład Zadanie 4: wyliczenia i numerowania;
  • autora i datę: kto i kiedy zapisał zmianę;
  • hash: unikalny identyfikator, na przykład e32ebb1. Git oblicza go z zawartości plików, dlatego żadne dwa różne commity nie mają takiego samego hasha;
  • rodzica: poprzedni commit. Dzięki temu commity tworzą łańcuch, czyli historię.

Co daje historia

  • Powrót do dowolnej wersji. Zepsułeś stronę w zadaniu 6? Możesz wrócić do stanu po zadaniu 5.
  • Zmiany widoczne linia po linii. Git pokazuje różnicę (diff) między dwoma commitami: zielone linie doszły, czerwone zniknęły. Strony „Wyjaśnienie i zmiany” w zadaniach HTML pokazują dokładnie takie różnice.
  • Opis każdej zmiany. Po miesiącu wiesz, dlaczego coś zmieniłeś.
  • Kopia zapasowa. Historia jest także na GitHubie. Awaria komputera nie usuwa Twojej pracy.
  • Praca w zespole. Kilka osób zmienia ten sam projekt, a Git łączy ich zmiany.

Już robisz commity

W zadaniach 1-3 wgrywasz pliki przez stronę GitHuba: Add file → Upload files, a na końcu przycisk Commit changes. Ten przycisk tworzy commit. GitHub sam wpisuje opis Add files via upload. Dlatego pierwsze commity w historii Johna mają takie opisy.

Strona WWW jest wygodna dla jednego pliku. Przy wielu plikach i częstych zmianach szybciej działa Git na Twoim komputerze. Tego uczą następne lekcje.

Ćwiczenie

  1. Otwórz swoje repozytorium na GitHubie.
  2. Nad listą plików kliknij napis z liczbą commitów, na przykład 4 Commits.
  3. Kliknij jeden commit. Zobacz, które linie są zielone, a które czerwone.

Sprawdź się

Co to jest commit?

Zapisany stan całego projektu w jednej chwili, z opisem, autorem, datą i hashem.

Dlaczego dwa różne commity nie mają takiego samego hasha?

Git oblicza hash z zawartości plików i z danych commita. Inna zawartość daje inny hash.

Czy w zadaniach 1-3 robisz commity?

Tak. Przycisk Commit changes na GitHubie tworzy commit.
