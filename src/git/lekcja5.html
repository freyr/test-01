Aby wysłać commity na GitHub, Git musi udowodnić, że to Ty. Hasło do konta tu nie działa. Najwygodniejszy sposób to klucz SSH: konfigurujesz go raz i więcej nie wpisujesz żadnego hasła.

Jak działa para kluczy

Polecenie ssh-keygen tworzy dwa pliki, które pasują do siebie:

  • klucz prywatny id_ed25519: zostaje tylko na Twoim komputerze. Działa jak klucz do drzwi.
  • klucz publiczny id_ed25519.pub: kopiujesz go na GitHub. Działa jak zamek, który pasuje tylko do Twojego klucza.

Przy każdym połączeniu GitHub sprawdza, czy masz klucz prywatny, który pasuje do zamka na Twoim koncie. Sam klucz prywatny nigdy nie jest wysyłany.

Klucz prywatny jest jak hasło. Nie wysyłaj go nikomu, nie wklejaj na GitHub, nie wgrywaj do repozytorium. Na GitHub kopiujesz tylko plik z końcówką .pub.

Krok 1: utwórz klucz

Wpisz polecenie z Twoim e-mailem. Na trzy pytania odpowiedz klawiszem Enter: domyślne miejsce pliku i puste hasło do klucza.

{{sesja ssh 1-1}}

Obrazek z kreskami (randomart) to graficzna wersja odcisku klucza. Nie musisz go zapamiętywać.

Hasło do klucza (passphrase) chroni klucz, gdy ktoś skopiuje plik. Na własnym komputerze możesz je pominąć. Na komputerze szkolnym ustaw hasło albo usuń folder ~/.ssh po lekcji.

Krok 2: skopiuj klucz publiczny

{{sesja ssh 2-3}}

Zaznacz całą linię od ssh-ed25519 do adresu e-mail i skopiuj ją. W Git Bash kopiujesz zaznaczeniem myszą i wklejasz klawiszami Shift + Insert. W Git Bash zadziała też polecenie clip < ~/.ssh/id_ed25519.pub, na macOS pbcopy < ~/.ssh/id_ed25519.pub. Kopiują one klucz do schowka.

Krok 3: dodaj klucz na GitHubie

  1. Na GitHubie kliknij swój awatar w prawym górnym rogu i wybierz Settings.
  2. W menu po lewej wybierz SSH and GPG keys.
  3. Kliknij New SSH key.
  4. W polu Title wpisz nazwę komputera, na przykład Laptop w domu.
  5. W polu Key wklej skopiowaną linię.
  6. Kliknij Add SSH key. GitHub może poprosić o hasło do konta.

Każdy komputer ma swój klucz. Na GitHubie możesz dodać kilka kluczy: z domu, ze szkoły, z laptopa.

Krok 4: sprawdź połączenie

{{sesja ssh 4-4}}

Przy pierwszym połączeniu SSH pyta, czy ufasz serwerowi. Porównaj odcisk z tym, który GitHub podaje na stronie GitHub's SSH key fingerprints. Odcisk ED25519 to SHA256:+DiY3wvvV6TuJJhbpZisF/zLDA0zPMSvHdkr4UvCOqU. Gdy się zgadza, wpisz yes.

Napis Hi johndoe! You've successfully authenticated oznacza sukces. Zdanie „GitHub does not provide shell access” to nie błąd. GitHub tylko informuje, że nie można się na nim zalogować jak na zwykły komputer.

Typowe błędy

KomunikatPrzyczyna i rozwiązanie
Permission denied (publickey)GitHub nie zna Twojego klucza. Sprawdź, czy dodałeś plik .pub na swoim koncie (krok 3).
Could not resolve hostnameBrak internetu albo literówka w github.com.
Prośba o login i hasło przy git pushRepozytorium ma adres https://. Klonuj adresem SSH git@github.com:... (lekcja 6).

Ćwiczenie

  1. Utwórz klucz poleceniem ssh-keygen.
  2. Wyświetl klucz publiczny i dodaj go na GitHubie.
  3. Sprawdź połączenie. Czy GitHub pisze Twoją nazwę użytkownika?

Sprawdź się

Który plik kopiujesz na GitHub?

Tylko klucz publiczny: ~/.ssh/id_ed25519.pub.

Kolega prosi o Twój plik id_ed25519, „żeby też mógł wysyłać”. Co robisz?

Odmawiasz. Z tym plikiem kolega może zmieniać wszystkie Twoje repozytoria. Kolega tworzy własny klucz, a Ty dodajesz go jako współpracownika repozytorium.

Czy przy każdym git push wpisujesz hasło?

Nie. Klucz SSH loguje Cię automatycznie.
